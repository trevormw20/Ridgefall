# Ridgefall — Tactical RPG Prototype (v0.1)

A Final Fantasy Tactics–style turn-based tactics game built in plain HTML/JS/CSS.
Single-file output, no framework, runs in any browser (desktop + mobile).

## Project layout

```
src/
  engine.js       # ALL game logic (map, units, combat, skills, AI, rendering, debug)
  sprites.json    # generated pixel-art spritesheets, base64-embedded (do not hand-edit)
tools/
  gen_sprites.py  # procedurally generates the sprites -> writes src/sprites.json + PNGs
  build.py        # inlines sprites.json + engine.js into one HTML file -> dist/
  v_*.png         # generated sprite sheets (reference; regenerated by gen_sprites.py)
dist/
  ridgefall_v0_1.html   # the built, playable game (generated — do not hand-edit)
spec/
  *.md            # the design specs these were built against
```

## How to build

The playable file `dist/ridgefall_v0_1.html` is **generated**. Never edit it by hand —
edit `src/engine.js`, then rebuild:

```bash
cd tools
python3 build.py        # -> writes dist/ridgefall_v0_1.html
```

To change or add character art, edit `tools/gen_sprites.py`, then:

```bash
cd tools
python3 gen_sprites.py  # regenerates src/sprites.json (+ PNG previews)
python3 build.py        # rebuild the game
```

Requirements: Python 3 with Pillow (`pip install pillow`). Node is only used for a
quick parse-check, not required to build.

## Current state (v0.1)

Playable: 10x10 grid, flat terrain with tags (high ground, cover, fire, blocked),
individual-unit turn order by SPD, spec-exact hit/damage formulas, Reaction Points
with Classic-Mode reactions, confirm-tap targeting, move-only undo, zoom/pan camera,
and a debug panel (battle-setup loader 0–5, infinite move/actions/HP/RP, kill/revive).

**6 jobs implemented:** Warder, Duelist, Lanternist, Bowman, Ember Cantor, Courier —
each with 4 skills, a reaction style, and correct stats.
**3 enemies:** Raider, Archer, Spark Caster.

### Known gaps / next tasks
- **Overwatch & Snap Aim** set their stance but do NOT yet fire a reactive shot when an
  enemy moves into range (needs a reaction-on-movement system).
- **Battle 4 rescue objective**: roster loads, but there's no NPC unit or rescue
  win-condition yet — victory is still "defeat all."
- **Wait speed bonus** (Turn Charge −80 on wait) from the spec is not implemented;
  turn order is a simpler SPD sort.
- Statuses use a simple tick duration rather than precise per-round expiry.
- No line-of-sight checks (ranged range is pure distance).

## Debug panel
Tap the **DEBUG** tab on the right edge. Includes: Load Battle 0–5, infinite
move/actions/health/RP toggles, per-slot kill/revive (K1–K6 / R1–R6), heal-all,
kill-enemies.

## Design specs
See `spec/`. Build order and scope are defined there; the guiding rule is to keep the
v0.1 slice small and prove the core loop is fun before expanding to more jobs/races.
